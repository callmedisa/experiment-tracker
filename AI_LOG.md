## Where the agent or a tool was wrong
1. **Agent code bug (found by the agent's own test):** a run id containing a NUL byte (`run_%00`) made asyncpg raise and the API returned 500 instead of the uniform 404. Fixed with `_lookup_id()`. Raw failing run kept: `results/api-tests-20261111-first-run-1-failure.txt`. JOURNAL: problem.
2. **Agent test bug:** `test_two_concurrent_revokes...` revoked the key its own session used, so it failed about 1 run in 25 (old version). Rewritten to assert the real invariant; 40/40 passes after. Raw failing run kept: `results/api-tests-20261111-150202.txt`. JOURNAL: problem.
3. **False confidence from the test harness:** 65 green tests, but the real container crashed on start (`alembic` console script could not import `app`; the fixture used `python -m alembic`). Found only by a manual smoke test. Fixed with `prepend_sys_path = .`. JOURNAL: problem.
5. **Agent performance bug, found by accident:** the point_id dedupe query became O(rows in run) while table statistics were missing (batch time 0.018 s → 0.49 s, then back). Found because a test assertion looked wrong, not by design. Fixed with a LATERAL probe. JOURNAL: surprise.
6. **Agent test bugs (3):** an integrity test posted an invalid batch without checking the status; the slow-reader test compared unequal baselines; two stream tests could hang instead of fail. All fixed, raw failures kept.
7. **Agent UI bug:** an extra redirect route made `/runs` render nothing (blank page). Two wrong hypotheses first (render crash; build problem); found by reading the route table. JOURNAL: problem.
8. **Agent logic bug:** connection watchdog treated timestamp 0 as "none" (found by a unit test, no user impact).
9. **Spec/agent mismatch found late:** server accepted `step` up to 2^62 which JavaScript cannot represent; found while building the checksum fixture, not when the API was written in step 2.
10. **Wrong diagnosis:** a 502/`<html>` failure was blamed on nginx caching the API's address; the real cause was an API crash from a malformed env var (zsh did not split `$ENVV`). I changed nginx.conf on the wrong theory and kept the change, flagged as unproven. JOURNAL: problem.
11. **Test too weak, then too cumulative:** the first E2E passed while most cuts hit nothing; later the chaos counters were cumulative, so a "lost responses > 0" assertion could pass on earlier seeds' losses. Both fixed. JOURNAL: surprise, problem.
12. **False claim in my own code and journal:** I wrote that the page renders at most 10 times per second; it rendered on every event. Found only because a configuration mutation made the page replay 13,000 events (>90 s). Fixed; ~2 s now. JOURNAL: surprise.
13. **Missing feature the spec asked for:** no request logging (spec §7 wants `request_id` in logs); noticed when the log-secrets test captured nothing. JOURNAL: problem.
14. **Gateway behaviour I had not looked at:** nginx's own HTML 400 for malformed URLs and its version header; four wrong nginx configurations before the working one. JOURNAL: surprise.
15. **Wrong assumption in a test:** `X-Accel-Buffering` is not visible to clients (nginx consumes it).
16. **Tests that hung instead of failing** (in-process stream calls) and a mutation log with missing lines and an unrun stub header. JOURNAL: problem.
17. **Measurement tool distorted the measurement:** the load generator's blocking resource sampler stalled its own event loop, inflating p95 latency about 7x (204 ms vs 28.8 ms) and the maximum to 3.1 s in the first full run. Noticed because p50 and p95 were far apart, confirmed on the raw samples, fixed, re-run. JOURNAL: problem.
18. **README that did not work on a clean machine:** `make test-web` failed (`tsc: command not found`) because nothing installed node packages; the README also claimed 8 E2E seeds while the code ran 5. Found only by the clean-clone check, after six steps of work described as "done".
19. **Wrong claim about CSS, from memory:** I had logged (spec-gap #25) that `container-type: inline-size` would make `.trk` the containing block for fixed dialogs. Measured in two Chromium builds: it does not. My "safer" portal then broke hit-testing in Playwright's Chromium because the fixed wrapper kept `container-type`; fixed with `container-type: normal`. JOURNAL: surprise.
20. **A mutation check that did not run, and a test too weak to catch it:** for the chart zoom I broke the code with `sed -i` (macOS sed rejected it), restored the file, ran the test, and saw it pass — a pass that proved nothing; I only noticed because the grep for the changed line printed an error. Also my first version of the zoom test checked the keyboard window, not the canvas window, so even a correctly applied mutation would have passed. Fixed by exposing the canvas x window (data-xmin/xmax) and asserting it, and by applying the mutation with an asserted Python replace. The invalid output is kept as `results/e2e/INVALID-mutation-not-applied-sed-failed.txt`.
4. A first attempt to write several files in one shell command was blocked by the tool's safety check (the command contained no deletion; the parser could not verify it). Nothing ran. The files were written with the file-write tool instead.

## Things the agent claims that are NOT verified
Resolved since the first version of this list (see JOURNAL): `container-type` vs `position: fixed` was tested and my claim was wrong (spec-gap #25 entry, results/ui/fixed-position-experiment.md); `GET /runs` is still unmeasured at 500 runs (below).

- That `crypto.subtle` is secure-context only, and that Postgres folds unquoted `NOTIFY`/`LISTEN` channel identifiers to lower case. From memory, not tested (the code works either way).
- `GET /runs` with hundreds of runs: no measurement exists (the load test used 50 runs and did not load the list).
- The 5–7 h scope concern is a judgment, not an estimate.
- That the tests exercise the same code that runs under `docker compose up`: mostly yes for E2E and stack tests (real nginx and uvicorn), only partly for the API tests (in-process, plus a real-uvicorn fixture for streams).
- That the timing test proves timing equality: it is a statistical check of one route over 400 samples per variant on a laptop with Docker; a 0.2 ms difference was measurable (long ids).
- That the E2E test would catch every kind of data loss: a page that silently drops events but repairs them through gap-fill is not caught (shown by mutation).
- That the mutation checks mean the suites are thorough: they show that the listed breakages are caught, nothing more. Several isolation mutations (I-M5 and the "not run" rows in results/evidence-map.md) were not run.
- Browsers and devices: Chromium only (the app pane and Playwright 129). Firefox, Safari, a real phone, a screen reader, an automated contrast check were not used. Dark theme was looked at on three pages only.
- Zoom and keyboard stepping: x-axis zoom by mouse drag only; not tested with touch, wheel or a screen reader (the readout announces every step).
- Everything ran on one laptop with Docker Desktop; the load test is one 10-minute run with the shipped defaults; no second run to show variance.
- Rate limits, the stream hub and last-used throttling are in-process: only correct with ONE api process. Not tested with two.
- The npm-audit exposure: 2 runtime findings (react-router) and 8 dev-tool findings, none upgraded; whether the router advisories are reachable here was not tested (results/npm-audit-summary.md).
- The lost browser session is unexplained (JOURNAL, "Lost browser session"); I found and fixed a different bug (500 after a Postgres restart) while looking.
- The public default SERVER_PEPPER is only warned about, not refused: a stack started without `make pepper` runs with it.
- Expired session rows are never deleted (unbounded growth of the sessions table); the retention of runs and events is also unbounded.
- Local path `/Users/disa` appears in 5 raw result files (never edited, as required); the repository is committed with them.
