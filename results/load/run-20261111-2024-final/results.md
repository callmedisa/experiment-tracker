## What was not measured here

- the load generator ran on the same machine as the stack (it competes for CPU); Docker Desktop on one laptop; one API process; no network latency
- stream delay is an upper bound that includes ingest time; the server's own `received_at` was not compared (host and container clocks)
- browsers were not used: readers are HTTP clients, so rendering cost of the UI under this load is not in these numbers
- no chaos proxy and no fault hooks in the path; failures other than the periodic client-side disconnects were not injected
- the database already held earlier test data (see settings.txt); a fresh database was not used
